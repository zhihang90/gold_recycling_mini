01结论与设计原则

充值本质是「支付机构给用户开钱包 + 给一个可识别的收款账户」，用户从手机银行转账，机构识别入账并通知； 提现本质是「把钱包可用余额退回本人同名卡」。两者共用一套钱包、一套余额、一套流水。
  • 先开户再收付：注册即实名 + 绑同名卡，支付机构侧开立钱包；未绑卡不可充值、不可提现。
  • 余额分层：可用 / 冻结分开，可提现为按来源派生；提现提交即冻结，失败自动解冻。
  • 未知态不等于失败：超时或网络异常一律停留「处理中」，查询确认后才能收敛为成功或失败。
  • 回调为主、查询为辅、余额兜底：余额变化不能单独作为某笔充值/提现的记账依据。
  • 可解释：每个页面都要回答「钱在哪、多久到、失败了怎么办」。

可提现余额 = 可用余额 − 未满 D+1 的充值本金；冻结金额不计入可用余额，无需再减。

充值资金流

用户银行卡 → 支付机构备付金账户 → 用户钱包余额（可用）。

提现资金流

钱包可用 → 冻结 → 机构出款 → 用户同名银行卡；失败回到余额。

流水统一：场景固定为「充值 / 提现 / 购金支出 / 回收到账 / 售后退款」，终态固定为 处理中 / 交易成功 / 交易失败，页面状态标签不再自造“已到账、已支付、已退回”等同义状态。

4.2 收款识别与充值限额

  • 专属收款账号：为每个用户分配唯一账号，格式为 001 + 钱包编号；户名为签约名，开户行为支付机构备付金集中存款账户，开户地以机构返回为准。
  • 自动识别：用户从本人同名卡向该账号转账，金额与充值单一致即自动入账，无需填写汇款备注。
  • 充值限额（可配置）：单笔 100~50,000 元、单日 100,000 元、单月 500,000 元；免手续费，页面不展示手续费字段。

4.4 充值单生命周期与断点恢复

  • 单量限制：同一用户同一时间只允许 1 笔「待转账/检测中」充值单；新建时自动关闭旧单，避免固定专属账号下多单金额无法区分。
  • 断点恢复：用户离开或杀进程后，再次进入充值页优先恢复未完成充值单（金额、收款信息、剩余有效期），不重复创建。
  • 未点检测也已到账：机构回调/查询命中后直接入账，并通过站内消息与推送告知；用户下次进入看到“已到账”。
  • 关闭后到账：充值单超时关闭后资金才到账 → 优先匹配最近一笔关闭单；无法匹配则进入「待认领」，客服凭回单认领或原路退回。
  • 充值单有效期：30 分钟未转账自动关闭；专属账号长期有效，但仅当前有效单可自动入账。

05充值：到账检测（核心）

三层确认：机构回调为主 → 充值单查询为辅 → 钱包余额查询兜底。 余额查询只能发现“有未认领资金”，不能单独证明是哪一笔充值。
层级谁发起用途
回调 notify支付机构 → 我方后端主链路，验签后幂等入账
充值单查询我方后端 → 支付机构回调丢失/延迟时补偿
余额查询我方后端 → 支付机构兜底发现未认领资金，不直接记账

5.1 轮询节奏（后端代理，前端不直连机构）

阶段间隔说明
0 ~ 30 秒3 秒实时转账多在此阶段到账
30 秒 ~ 2 分钟5 秒跨行/普通到账
2 ~ 10 分钟15 秒降低机构查询压力
> 10 分钟停止转“延迟到账”，保留手动刷新/回单
  • 页面不可见暂停轮询，回前台立即查一次；同一用户同一时间仅 1 个等待页。
  • 后端对机构查询做单飞 + 短缓存（如 2 秒），避免多端并发触发限流。
  • 终态立即停止轮询并写流水。

5.2 银行汇款能力与约束

能力规则与产品落点
到账时效7×24 可转账，通常 5 分钟内自动入账
支持银行仅支持机构可识别的银行范围；充值页需提示可用银行，避免用户从不受支持银行转账
回调与查询支持异步回调 + 主动“充值结果查询”补偿；回调验签后幂等入账
余额查询频控单用户单订单 ≤ 1 次/3 秒；机构级 QPS 以接入协议为准，超限指数退避，前端不直连
退票与退回账号/户名不符、产品未开通、付款人超限等按机构与银行规则退回，通常 1~3 个工作日；需保留凭证并支持客服查询
不要用余额差直接记账：回收到账、退款、提现退回都会改变余额；最终记账必须以充值单 + 机构流水号为准。

6.1 异常处理机制

资金落点：用户可用余额 / 退款在途 / 待认领挂账 / 机构处理中，定义与科目见 11.1。充值特有约束：待认领资金不计入用户余额，7 天未认领原路退回。

三层兜底：自动（查询重试 + T+1 对账补偿）→ 半自动（工单 + 客服凭回单处理）→ 人工（财务调账，双人复核），详见 11.2。任何一层都不能绕过“先有机构流水、再改用户余额”。

6.2 充值异常矩阵（含资金落点与兜底）

异常话术模板（充值 / 提现通用，9.2 同此规范）：
  • 一句话结构：现象或资金状态 + 下一步动作，≤ 30 字；先讲“钱在哪”，再讲“怎么办”。
  • 三类句式：需用户处理 →「{问题}，请{动作}」；资金在途 →「正在处理，预计 {N} 小时内{结果}」；系统内部问题 → 用户无感，仅结果通知。
  • 状态词：异常文案里的资金状态只用「处理中 / 交易成功 / 交易失败」，未确认时不说“失败”；单据自身状态（待转账、延迟到账、待认领、已关闭等）按各章状态表展示。
  • 对外禁用词：回调 →「到账通知」；单边账 →「对账差异」；退票 →「银行退回」；解冻 →「回到余额」；幂等 / 记账 / 调账等内部词不出现。
  • 出入账口径：充值退回说“退回原卡”，提现退回说“回到余额”；金额用 {金额}，时长用 {N 小时} / {N 个工作日}。
异常识别资金落点用户可见兜底与时限
户名/账号错误匹配失败或机构入账失败退款在途「收款信息有误，资金已退回原卡，请核对后重试」自动跟踪退票；T+3 未退回升级工单，客服凭回单核对
非同名付款付款人与实名不符退款在途「仅支持本人同名账户转账，请更换付款卡」拒绝入账并自动退回；同户名多笔触发风控复核
金额不一致匹配成功但金额不等实际金额入可用；多转的差额进待认领，少转不补记「已按实际到账 {金额} 入账，差额将另行确认」2 小时内客服确认差额：补转 / 退回；财务调账双人复核
重复转账同一账号短时多笔每笔分别入可用；无法匹配部分挂待认领「已分笔入账，请查看资金流水」对账校验总额；多余资金 7 天未认领原路退回
银行延迟超 10 分钟未确认机构/银行在途「到账可能延迟，可刷新或上传回单」继续查询至 T+1 对账；超 24 小时生成工单
回调丢失对账发现单边账机构已入账、平台未记无感（到账后通知）定时查询 + T+1 对账自动补记；补记失败转人工工单
关闭单后到账资金晚于 30 分钟有效期优先匹配最近关闭单入可用；否则待认领「转账已收到，正在核对入账」2 小时内响应；7 天未认领原路退回
我方记账失败机构成功、本地事务失败机构已入账，平台待补记「到账处理中，请稍后刷新」事务补偿任务重试；仍失败则人工补记，双人复核，禁止用户重复转账
钱包受限/冻结钱包状态校验不通过资金挂待认领「账户暂受限，资金已收到，请联系客服」风控复核后解限入账或原路退回，2 小时内给结论
并发/重复创建充值单唯一键冲突不产生资金变动无感（恢复原充值单）唯一键 + 状态机拦截；监控重复率

09提现：异常与退票

9.1 异常处理机制

  • 未确认不出款、不释放：机构未给出终态，冻结金额保持冻结，不允许人工提前解冻。
  • 失败必解冻：明确失败或退票确认后，冻结 → 可用，并写「提现 / 交易失败」流水。
  • 差异挂账、不改余额：机构已出款但本地记账失败时，冻结继续保留，补记后再扣减；禁止先解冻造成双花。
  • 一单只出款一次：提现单号 + 机构流水号唯一键，重复回调/重复提交均幂等。

资金落点（可用 / 冻结 / 退款在途 / 待补记）与科目定义见 11.1。

11.3 基础安全机制

  • T+1 三方对账：我方单据 ↔ 机构流水 ↔ 银行明细；差异自动生成工单。
  • 单边账：机构已记账我方无单 → 补单/待认领；我方有单机构无记录 → 暂停并人工核查。
  • 幂等与唯一键：充值单号/提现单号 + 机构流水号唯一；状态只前进不回退。
  • 余额并发：乐观锁/版本号，冻结与扣减在同一事务；失败解冻可重试。
  • 权限与审计：人工认领、强制失败、退款、冻结需双人复核并留日志。
  • 密钥安全：机构密钥只在服务端，前端不接触机构接口。

14验收用例

14.1 充值

  1. 未绑卡用户被拦截并引导绑卡；绑卡后正常充值 1,000 元，60 秒内到账，余额 +1,000，流水「充值/交易成功」。
  2. 银行延迟：超 10 分钟未确认转延迟到账，刷新后自动入账；上传回单可转客服加急。
  3. 金额不符：充值单 1,000 实际 900，按 900 入账并提示差额；多转 50 元时差额进待认领，客服 2 小时内确认。
  4. 非同名：拒绝入账并原路退回。
  5. 重复转账：两笔均入账，生成两条流水；无法匹配部分进待认领。
  6. 回调丢失：T+1 对账自动补记，余额与流水一致，用户无感。
  7. 我方记账失败：机构成功、本地失败，补偿后仅入账一次，不产生重复余额。
  8. 关闭充值单后到账：超时关闭后转账到账，自动匹配最近关闭单入账并推送通知；7 天未匹配则原路退回。

14.2 提现

  1. 可用 5,000 提现 2,000：可用 3,000 / 冻结 2,000；成功后冻结清零，流水「提现/交易成功」。
  2. 余额不足：超可提金额被拦截，按钮置灰并提示剩余可提额度。
  3. 失败退回：模拟退票，冻结回到可用，流水「提现/交易失败」。
  4. 重复提交：连续点击仅一笔，第二笔提示处理中。
  5. 断网超时：恢复后按单号查询，不重复扣款。
  6. D+1 可提：当日 15:00 充值 1,000 元，当日提现被拦截并提示“D+1 可提”；次日 00:00 后该金额进入可提现余额。
  7. 夜间提现：23:00 提交 2,000 元，仍按 T+0 受理并到账，页面显示通常实时、最迟 2 小时内。
  8. 解绑卡后到账：提交提现后解绑该卡，提现单仍按原卡结算成功，详情展示原卡尾号。
  9. 断点续查：提交后关闭 APP，重新进入提现详情仍能查到最新状态。
  10. 退票冻结时点：退票确认前保持冻结，确认后解冻回可用并写「交易失败」，全程不重复出款。
  11. 未知态收敛：提交超时后仅查询不重提；24 小时未收敛转对账，机构无单自动解冻。
  12. 记账失败：机构已出款、本地失败时冻结不提前释放，补记后扣减，避免双花。

  • 充值本金 D+1 可提：充值成功次日 00:00 起计入可提现余额（见 7.3）。
  • T+0 由支付机构垫资：7×24 随时可提，平台不垫资；仅通道维护转 T+1（见 7.2）。
  • 全链路免手续费：充值与提现均 0 元（见 4.2、7.2）。
  • 到账卡：最多 5 张本人同名储蓄卡，默认卡唯一；可随时解绑（含最后一张）、直接切换，无冷静期；处理中提现按原卡结算（见 2.2）。
  • 机构能力：专属收款账号（001+钱包编号）、7×24 约 5 分钟自动入账、回调 + 结果查询、退票 1~3 个工作日、余额查询 ≤1 次/3 秒（见 4.2、5.2）。
  • 回收到账：不单独设提现限额，共用单笔/单日/笔数限制（见 7.3）。
  • 二类户限额：已在“添加银行卡”页提示，本方案不重复设计（见 2.2、12）。

15.2 联调确认项

业务规则已全部确认，无待决项；上线前与支付机构联调时确认余额查询实际 QPS、退票退回实际时效、通道维护公告方式即可，不改变本方案流程与页面。
