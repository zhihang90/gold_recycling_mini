## 1. 业务边界与目标

### 1.1 业务定位

安盛华黄金回收业务首期定位为：**面向个人客户的线上邮寄黄金回收闭环服务**。用户通过微信小程序完成看价、估价、下单、协议确认与寄件；安盛华钟表公司为回收与付款主体并运营小程序，安盛华集团负责检测，物流与保价方承接邮寄履约，完成终价确认、支付、退回与售后。长期方向服务于“投资金销售＋黄金回收”双业务规划。


### 1.2 业务目标

首期目标不做全品类，先把邮寄黄金回收主闭环跑通，并保证交易可信：

1. **寄件前规则透明**：品类、金价、估价逻辑、费用、强制保价、默认破检、终价与退回规则在寄件前可理解。
2. **终价可解释**：实际可熔重量、纯度、结算金价时点、费用扣减与应付金额完整展示，与预估差异可解释。
3. **每个节点有出路**：接受/拒绝终价、付款失败、更换账户、物流异常均有明确处理路径。
4. **全程记录可查**：主体、物品、协议、电子签、物流、检测、终价、支付、退回、客服记录关联同一订单。
5. **为双业务留底座**：账户、订单、协议、支付、售后能力可复用，但与投资金销售在主体、资金、协议上隔离。

### 3.6 订单状态流转设计

#### 3.6.1 对象模型与职责边界

| 对象 | 回答的问题 | 状态归属 | 与订单的关系 |
| --- | --- | --- | --- |
| 回收订单（业务单） | 这单生意进行到哪一步 | 订单主状态（共 9 个） | 主对象，串联全部单据与记录 |
| 物流单（寄出/退回） | 货到哪了 | 物流状态流转 | 一单一状态；寄出运单的揽收/签收事件带动订单主状态流转；拦截原路退回复用寄出运单轨迹，拒收/拒绝终价退回新建退回运单 |
| 付款单 | 钱付没付成、失败为什么 | 支付状态流转 | 一个订单对应一笔付款义务，可有多次支付尝试；支付成功事件驱动订单进入已完成 |
| 检测工单 | 检测结果出没出、有无差异 | 内部状态（清单见下表） | 只向订单输出结果（检测完成/信息不符复核），用户不直接见工单状态 |

**各单据状态清单与对订单主状态的驱动关系：**

| 单据 | 状态清单 | 驱动订单主状态的事件 | 用户可见性 |
| --- | --- | --- | --- |
| 物流单·寄出运单 | 待揽收 → 运输中 → 已签收；异常（破损/丢失/超时/拒收）走人工工单，不进状态链 | 揽收 → 订单「待寄出」转「待签收」；签收 → 「待签收」转「检测中」 | 轨迹对用户可见（「邮寄运输」阶段内展示） |
| 物流单·退回运单 | 待揽收 → 运输中 → 已签收 | 退回签收 → 订单转「已关闭」 | 退回单号与轨迹在「退货·取消」订单详情可见 |
| 付款单 | 待支付 → 支付中 → 支付成功／支付失败（限额/账户不符，可更换本人支付宝账户重付）／异常待复核（人工复核）；风控拦截挂「待支付」上的标记，不发出付款指令 | 支付成功 → 订单「待打款」转「已完成」；失败/异常不驱动主状态，订单停留「待打款」 | 用户只见「正在打款」子节点与失败提示层 |
| 检测工单 | 待检测（签收＋开箱留证后生成）→ 检测作业中 → 检测完成；差异分支：信息不符复核中 → 复核完成 | 检测完成 → 订单「检测中」转「待确认」；复核不驱动主状态，仅以提示层呈现 | 内部状态，用户只见检测直播/回看、检测结果与差异说明 |

设计原则：一个字段一个职责；状态只朝一个方向流转，最终状态不可再变；取消/退回等逆向分支进最终状态，不倒退；定时任务首期仅终价超时自动接受一个，物流揽收/签收、付款成功为事件驱动，审核通过为人工预审触发；未寄出不自动关闭、不自动提醒（超预约取件时间 2 个工作日人工跟进，见 3.6.6）。

#### 3.6.2 订单主状态一览（共 9 个）

```javascript
【主链】审核中 → 待寄出 → 待签收 → 检测中 → 待确认 → 待打款 → 已完成

【分支与最终状态】
审核中 ──可修正驳回（照片不清晰/不完整、资料缺失）──→ 审核中（挂驳回标记，用户重新上传资料后重新排队，主状态不变）
审核中 ──风控复核不通过 / 不可回收，人工终止──→ 已关闭
待寄出 ──用户自助取消──→ 已取消
待签收 ──客服拦截退回 / 物流异常理赔完成后──→ 已关闭
检测中 ──人工判定拒收，退回签收后──→ 已关闭
待确认 ──用户拒绝，退回签收后──→ 已关闭
待打款 ──持续支付失败 / 风控不通过，人工关闭──→ 已关闭
任意进行中状态 ──风控复核不通过，人工终止──→ 已关闭
```

| 编码 | 状态 | 进入条件 | 用户可执行操作 |
| --- | --- | --- | --- |
| 1 | 审核中 | 订单创建成功，系统校验齐备性（实名＋电子签＋协议/来源/破检授权＋强制保价）后进入人工预审（照片/物品信息/风控核验）；下单时已锁定取件预约时段，预审须在预约取件时间前完成 | 等待审核结果（审核时效<span style="color:red">待填</span>）；不可自助取消，如需取消可联系客服；被驳回时查看具体驳回原因（照片/资料类）、重新上传资料重新排队预审 |
| 2 | 待寄出 | 审核通过（全部校验通过），取件预约生效 | 查看取件预约时间与寄件指引、等待快递上门揽收（<span style="color:red">是否保留自行寄件回填单号通道待确认</span>）、**自助取消（首期唯一取消点，联动取消取件预约）** |
| 3 | 待签收 | 寄出运单已揽收 | 查看物流轨迹；取消仅可联系客服拦截 |
| 4 | 检测中 | 平台签收＋开箱留证完成 | 等待结果；观看检测直播（结束后可回看完整检测视频）；信息不符时查看差异说明、配合复核 |
| 5 | 待确认 | 终价明细生成，启动 30 分钟倒计时 | **接受终价 / 拒绝并退回**；复检（二次检测）首期不做，二期规划（见 L-08） |
| 6 | 待打款 | 用户接受终价 或 超时自动接受 | 查看付款进度；支付失败时更换支付宝账户重付 |
| 7 | 已完成 | 付款单支付成功（最终状态） | 查看凭证、下载记录 |
| 8 | 已取消 | 待寄出状态下用户自助取消，或长期未寄出（超过预约取件时间 2 个工作日）经客服电话确认后由运营后台取消（最终状态） | — |
| 9 | 已关闭 | 拒收退回完成 / 拒绝终价退回完成 / 拦截退回或物流异常理赔完成 / 支付异常人工关闭 / 风控终止（最终状态，按关闭原因分类留痕） | 查看关闭原因与退回单号 |

关键设计点：

- **"审核中"为首状态**：订单创建即进入，系统校验齐备性后转人工预审，通过才允许交付包裹。预审不通过分两类：**可修正驳回**（照片不清晰/不完整、资料缺失）——挂驳回标记，展示具体原因＋重新上传入口，重传后清标记重新排队，主状态不变；**风控终止**（风控不通过、非开放品类等）——人工关闭，通用话术不披露规则。取件预约联动：下单时锁定时段，预审须在预约取件时间前完成；驳回期间预约保留，超预约时间未通过自动取消并通知、通过后重新预约；风控终止/人工关闭即时取消。
- **"支付异常"不进订单主状态**：订单到"待打款"即停，钱没付成是付款单的事；页面从付款单读取失败原因与操作入口。
- **"物流异常"不进订单主状态**：货在"待签收"卡住是物流单的事；异常只生成工单，人工判定订单走向，不做自动流转。
- **退回不算独立主状态**：拒绝终价/拒收 → 生成退回运单 → 退回签收 → 订单进"已关闭"；退回轨迹从退回运单查看。
- **检测直播不进订单主状态**：直播是"检测中"状态下的过程透明能力，只挂接、不新增状态，不影响既有 9 个状态口径与流转规则。

#### 3.6.3 物流状态流转（记录在物流单上）

- 寄出运单：`待揽收 → 运输中 → 已签收`；异常（破损/丢失/超时/拒收）另走人工工单处理。
- 退回运单：`待揽收 → 运输中 → 已签收 → 触发订单进入已关闭`。
- 事件驱动：揽收事件推订单 待寄出→待签收；签收事件推订单 待签收→检测中。异常不产生自动流转。

#### 3.6.4 支付状态流转（记录在付款单上）

```javascript
待支付 → 支付中 → 支付成功（最终状态，带动订单进入"已完成"）
             ├→ 支付失败（限额/账户不符）→ 更换本人支付宝账户 → 重新发起 → 支付中
             └→ 异常待复核（人工复核）→ 确认/更换账户 → 重新发起 → 支付中
```

- 触发方：终价确认后生成结算单，三一致（出售人/实名人/收款人）校验通过，系统自动发起付款（待支付 → 支付中）；风控命中则暂停，不发出付款指令。
- 每次重新发起为一次新支付尝试，旧尝试留痕；系统有防重复付款机制。
- 风控审核挂"待支付"上的拦截标记，不发出付款指令；用户侧统一显示"审核中"，不披露风控规则。
- 退回物流与资金状态分别闭环（A-12 口径不变）。

#### 3.6.5 主状态流转规则

| 状态流转 | 触发方 | 前提条件/规则 | 必须留痕 |
| --- | --- | --- | --- |
| 创建 → 审核中 | 系统 | 提交订单即创建并进入校验；保存估价记录 | 协议版本、签署证据、估价记录 |
| 审核中 → 待寄出 | 人工预审 | 系统校验齐备性通过后，人工预审照片/物品信息/风控核验通过，取件预约维持有效 | 预审记录、审核人、审核通过时间 |
| 审核中 ⇄ 审核中（驳回标记） | 人工预审 / 用户 | 预审发现可修正问题（照片不清晰/不完整、资料缺失）→ 挂驳回标记并通知用户，取件预约保留；用户按驳回原因重新上传资料 → 清标记、重新排队预审；超过预约取件时间仍未通过的自动取消预约并通知用户，通过后重新预约；主状态不变，不计入流转 | 驳回原因、重新提交记录、次数 |
| 审核中 → 已关闭 | 系统 / 人工 | 风控复核不通过或不可回收（非开放品类等），人工复核后终止，即时自动取消取件预约；用户侧展示通用关闭话术，不披露风控规则 | 复核结论、终止原因、预约取消记录、责任人 |
| 待寄出 → 已取消 | 用户 / 运营 | 用户自助取消为首期唯一取消点，无费用，自助取消即时联动取消取件预约；长期未揽收（超过预约取件时间 2 个工作日）经客服电话确认、用户不再寄出后由运营后台直接取消，不做自动取消 | 取消原因、时间、预约取消记录、跟进记录 |
| 待寄出 → 待签收 | 物流单揽收事件 | 单号有效且揽收 | 物流单号、保价信息 |
| 待签收 → 已关闭 | 客服/人工 | 客服拦截退回成功（原运单退回），或物流丢失进入保价理赔；退回签收或理赔完成后关闭 | 拦截/理赔工单、退回轨迹、关闭原因 |
| 待签收 → 检测中 | 物流单签收事件＋检测方 | 开箱留证、复称完成 | 开箱影像、复称记录 |
| 检测中 → 待确认 | 系统 | 检测工单完成，按检测完成时点金价生成终价明细 | 检测工单、终价版本、结算金价记录 |
| 检测中 → 已关闭 | 人工判定拒收 → 退回签收 | 非开放品类误寄等不符合回收条件 | 拒收原因、退回运单、签收记录 |
| 待确认 → 待打款 | 用户 / **定时任务** | 用户主动接受；或 30 分钟超时自动视为接受（窗口内提醒 1 次，站内消息＋手机短信；不允许二次议价） | 确认方式（主动/超时）、提醒记录、自动接受流转记录 |
| 待确认 → 已关闭 | 用户拒绝 → 退回签收 | 窗口期内拒绝并退回 | 拒绝原因、退回费用、退回运单 |
| 待打款 → 已完成 | 付款单支付成功事件 | 渠道确认到账 | 支付流水、到账凭证 |
| 待打款 → 已关闭 | 人工 | 持续支付失败或风控不通过，人工关闭 | 关闭原因、复核记录 |
| 任意进行中状态 → 已关闭 | 风控/人工 | 下单复核不通过、检测发现调包嫌疑、风控复核不通过等，人工复核后终止；用户侧展示通用关闭话术（如"订单无法继续服务"），不披露风控规则 | 复核结论、终止原因、责任人 |

**通用暂停机制**：风控拦截标记与争议工单为订单级机制，不只作用于付款。暂停期间，所在状态自动触发的流转（终价超时自动接受、付款发起）一并暂停，工单处理完结或风控放行后恢复；暂停期间对用户仅展示"审核中/处理中"。

#### 3.6.6 取消规则矩阵

| 订单状态 | 能否取消 | 处理方式 |
| --- | --- | --- |
| 审核中 | 不可自助取消 | 人工预审期间如需取消可联系客服；可修正驳回不关闭订单，用户可重新上传资料重新排队，驳回期间取件预约保留；风控终止由人工关闭并即时取消取件预约；驳回后长期未补充资料的由客服跟进，确认不再继续由运营后台关闭（不做自动关闭） |
| 待寄出 | 可自助取消 | 无费用，自助取消即时联动取消取件预约；首期 MVP 不做未寄出自动提醒与自动取消；超过预约取件时间 2 个工作日未揽收客服电话联系，用户不再寄出由运营后台直接取消 |
| 待签收 | 不可自助取消 | 联系客服拦截；<span style="color:red">拦截产生的运费/保价费承担规则待填明数（正常回收订单按公示口径执行）</span> |
| 检测中（已签收/已破检） | 不可取消 | 实物已不可逆改变，只能走"拒绝终价 → 退回" |
| 待确认 | 不可取消 | 交易决策中，窗口期内可拒绝 |
| 待打款/已完成 | 不可取消 | 交易已成立，资金问题走人工工单 |

#### 3.6.7 用户侧呈现：状态机／阶段／Tab 三层映射

用户侧不直接暴露系统状态机。呈现分三层，先明确三层定义：

**① 系统状态机（系统层）**：订单流转与风控的唯一口径，精细、完整——9 个订单主状态（见 3.6.2），物流单、付款单、检测工单的状态独立流转并驱动订单主状态（单据关系见 3.6.1，各自流转见 3.6.3–3.6.5）。面向开发、运营、风控，C 端不直接暴露。

**② C 端阶段（业务进度层）**：业务阶段，客观描述包裹/交易走到哪一步，共 5 段：订单审核 → 邮寄运输 → 专业检测 → 确认终价 → 交易完成。由平台侧驱动（系统事件与平台动作推进，用户操作只是触发源，不定义阶段），用户只能查看、无法操作阶段本身；呈现在订单详情页进度条，列表卡片上以阶段标签辅助展示。

**③ 列表 Tab（用户待办层）**：用户视角的关注点与待办——回答「现在需要我做什么、我最关心哪几单」，不是状态枚举。固定 5 个：全部／待寄出／待确认／已完成／退货·取消；呈现在订单列表顶部 Tab 及个人中心待办入口。

三层关系一句话：**状态机回答「这单生意进行到哪一步」（系统口径），阶段回答「包裹/交易走到哪一步」（客观进度，给用户看），Tab 回答「用户现在要做什么」（待办聚合）。**

**阶段 ↔ 系统状态映射：**

| C 端阶段 | 覆盖系统状态 | 阶段内用户操作与提示层 |
| --- | --- | --- |
| 订单审核 | 审核中 | 人工预审（照片/物品信息/风控核验），用户等待结果；被驳回时展示具体驳回原因（如照片不清晰/不完整）＋重新上传入口，重新提交后重新排队；仅风控终止时展示通用话术，不披露风控规则 |
| 邮寄运输 | 待寄出、待签收 | 待寄出：查看取件预约时间（下单时已预约）、寄件指引与包装要求、自助取消（首期唯一取消点，联动取消预约）；已揽收后：物流轨迹，物流异常横幅＋客服入口 |
| 专业检测 | 检测中 | 检测直播入口（直播中）/检测视频回看（结束后）；信息不符时提示「物品信息复核中，客服将联系你」；预计时效、破检提示回顾 |
| 确认终价 | 待确认、待打款 | 待确认：与预估差异解释、30 分钟倒计时最显著、接受/拒绝退回两选一；确认后进入子节点「正在打款」：展示付款方、金额、预计到账；支付失败时叠加失败原因＋更换账户按钮 / 「异常复核中」 / 「审核中」 |
| 交易完成 | 已完成 | 凭证下载、记录归档 |
| （旁路）退货·取消 | 已取消、已关闭 | 关闭原因（风控终止展示通用话术）；涉及退回的展示退回单号 |

注：提示层文案「审核中」（风控暂停、支付风控复核时展示）不等于订单处于「审核中」状态——前者是任意主状态下叠加的提示语，后者是订单主状态之一，开发与客服沟通时避免混淆。

**进度条口径（订单详情页）**：固定 5 段——订单审核 → 邮寄运输 → 专业检测 → 确认终价 → 交易完成；「待打款」不作为进度条主段，确认后以「正在打款」子节点呈现；「邮寄运输」段内区分「待寄出／运输中」两个子状态，审核通过后不得直接显示「运输中」（此时用户尚未寄件，避免文案穿帮）。

**列表 Tab 口径：**

| Tab | 纳入订单 | 定位 |
| --- | --- | --- |
| 全部 | 所有订单 | 中间等待态（审核中、运输中、检测中、打款中）仅在此以卡片阶段标签呈现，不单设 Tab；审核中被驳回待补充的订单在卡片上以醒目提示标签＋重新上传入口呈现 |
| 待寄出 | 「邮寄运输」阶段中处于待寄出状态的订单 | 用户第一行动点＋首期唯一自助取消窗口 |
| 待确认 | 「确认终价」阶段中处于待确认状态的订单 | 30 分钟倒计时，最强行动态 |
| 已完成 | 已完成 | 结果与凭证查询 |
| 退货·取消 | 已取消、已关闭（含拒绝终价退回、拒收退回、拦截退回、理赔关闭、人工关闭） | 售后与取消记录的统一出口 |

用户侧不设「异常」状态；页面结构 = 阶段标签 ＋ 提示层（从物流单/付款单/检测工单读取），异常只生成工单，由人工判定订单走向。

### 4.1 破检授权、不可还原提示与损耗口径草案

**关键条款速览建议文案：**

- 为确定黄金成色与可熔重量，安盛华集团检测人员可能对物品进行破坏性检测，包括但不限于剪开、压片、熔样、光谱/火试等检测方式。
- 破坏性检测可能造成物品形态、结构、焊点、配件、镶嵌物发生不可逆改变或灭失；即使后续退回，退回物也可能为检测后状态。

本人已阅读并理解：本次回收默认需要破坏性检测，检测过程可能不可逆改变或灭失物品原有形态、结构、焊点、配件或镶嵌物。本人知晓并同意检测过程将实时直播并全程录像存档（录像保存 3 年），直播与录像仅本人及平台授权人员可见，机位只拍摄检测台面操作区。本人同意安盛华集团按检测标准进行检测，并同意最终回收款按检测后的实际可熔重量、实际纯度、检测完成时点结算金价及已公示费用明细计算。检测及损耗规则以<span style="color:red">【规则版本/链接】</span>为准。

### 4.2 终价确认与超时规则草案

### 4.3 估价有效期草案

- 估价结果仅为提交订单前参考，有效期为<span style="color:red">【占位】</span>；超过有效期未提交订单，需重新估价。

### 4.4 支付异常处理草案

- 支付失败时，订单主状态保持"待打款"，失败状态与原因记录在付款单上；页面在待打款状态下展示失败原因和下一步操作；常见原因包括支付宝账户限额、账户信息不符、账户状态异常、风控审核、系统异常。
- 支付宝限额或账户信息不符：用户可更换本人支付宝账户，重新通过账户一致性校验后发起重付。
- 付款异常：付款单进入"异常待复核"，由人工复核账户信息；用户确认或更换收款账户后重付。
- 风控审核：涉及大额、可疑、频繁或异常交易的，暂停付款并进入人工复核；页面对用户展示"审核中"，不披露具体风控规则。
