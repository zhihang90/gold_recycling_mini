## 结论摘要

1. 租赁类产品的模块骨架是「**标的 → 定价 → 周期 → 押金/信用 → 物流交付 → 验货定责 → 结算 → 归还/再流通 → 售后 → 合同 → 消息 → 营销**」，其中真正决定用户体验的是 **「先给预期价、后按实物定损」这一段的表达是否可信**（Rentiqo 把 Return/Inspect/Charge 作为独立环节，爱回收把「线上预估 ≠ 最终报价」作为核心解释点）。**【搜索】**
2. 黄金回收与租赁的**同构点只有一个、但极其关键**：租赁是「预期完好 → 归还验货 → 按损耗扣款」，回收是「预期克重/纯度 → 破检 → 按实测定价」。两者的用户焦虑完全相同——**凭什么改价、改了多少、有异议怎么办**。
3. 异构点同样明确：回收**没有库存、没有租期、没有押金、没有续租/逾期、没有归还与维修清洗**；所有权是**单向转移**，不是「借出—收回」。**【推断，依据业务文档 L-01/L-04 与 3.7 状态机】**
4. 由此反推出的组件缺口，v1（按 UI 覆盖面盘点）没有覆盖到，集中在 **「报价基准」「物品规格」「差异对比」「检测结论」「准入前置」「分步进度」** 六处，全部属于「流程可信度」而非「控件齐全度」。
5. 本轮建议：**本期必须 6 个、后续预留 7 个、明确不做 12 类**。六个必须项全部可用现有 token 表达，不引入任何依赖。

### 1.2 四类垂直的差异点

| 维度 | 3C 数码租赁 | 奢侈品 / 珠宝租赁 | 以租代购（融资租赁） | 回收与二手交易 |
| --- | --- | --- | --- | --- |
| 标的状态 | 高周转、可复用、按序列号管理 | 稀缺款、按档期占用 | 车辆/设备，长期占用 | 一次性买断，形态不可逆（熔炼） |
| 核心风险 | 损坏、丢失、数据残留 | 损坏、真伪、保值 | 逾期、资产流失 | 报价争议、物品调包、洗钱 |
| 关键节点 | 发货验机 → 归还验机 | 交付验货 → 归还验货结算 | 申请 → 信审 → 签约 → 放款/交付 → 还款 | 线上预估 → 寄出 → 开箱留证 → 质检 → 终价 → 打款 |
| 独有模块 | 序列号台账、数据清除证书 | 档期日历、清洗消毒、保险 | 征信评分、分期计划、催收、GPS | 金价快照、破检授权、可熔重量折算 |
| 与回收的距离 | 中：验机报告可借鉴，押金/租期不可 | 近：验货结算与信任表达同构 | 远：金融属性完全不适用 | —（本体） |

**可直接借鉴的三件事【搜索 + 推断】**

1. 「验机报告」→「检测报告」：租赁把质检结论做成用户可逐项核对的报告，回收同样需要一个「结论 + 依据 + 影像」的展示单元。
2. 「归还按变化计费」→「终价按差异定价」：都需要**前置预期 vs 实测**的对照，而不是只给一个最终数字。
3. 「信用/准入闸门」→「实名 + 绑卡 + 协议 + 电子签」四道前置：租赁用信用分做闸门，回收用合规要素做闸门，界面形态一致（未完成项清单 + 跳转）。

| M11 消息与通知 | **部分适用** | 只做交易节点触达与站内消息，不做营销推送、不做逾期催收 | 消息行（预留）、Tab 分类（已有） |

### 2.2 四条否定结论（不要为了类比硬套）

1. **不做押金体系。** 租赁的押金/免押是「信用换现金流」，回收没有押金收退关系；把「保价」包装成押金会误导用户，保价是物流保障，不是用户资产。**【推断】**
2. **不做库存与档期。** 回收物的「量」不是可售库存，克重是估值参数；档期日历在回收里没有对应物。**【推断】**
3. **不做租期、续租、逾期、催收。** 回收的时效只有一个——终价确认 72h 窗口（U-18），它属于「确认倒计时」，已由 `CountdownBar` 承担，不需要周期管理组件。**【推断，依据 3.7 状态机】**
4. **不做维修/清洗/消毒/残值。** 这些服务于「物品要再次出租」；回收的物品直接进入检测与熔炼，生命周期在结算后结束。**【推断，依据 L-05】**

## 四、P0 组件明细

> 统一约定：间距只用 4/8/12/16/24/32；圆角只用 `rounded-xs/sm/md/lg/pill`；字号只用 role 类；金额、克重、时间加 `tabular`；可点区域 ≥44×44；支持 `className` 透传；组件内不写业务文案、不造数据。

### 4.1 `QuoteRateCard` — 参考金价卡

- **职责**：把「参考金价 + 来源 + 更新时间 + 有效性」作为一个不可拆的整体展示，避免页面各写一遍导致口径漂移。
- **变体**：`status: live | delayed | halted`；`trend?: { delta: number; label: string }`；`updatedAt: string`；`source: string`；`onExplain?`。
- **尺寸与字号**：`Card p-4`；标签 `text-label text-muted-foreground`；主值 `PriceText size="title" tone="gold" suffix="/克"`；来源与时间 `text-caption text-subtle-foreground tabular`；有效性 `Badge size="sm"`。
- **状态表达**：
  - 正常：主值 + 「较昨日 +2.4」`text-caption text-muted-foreground tabular`。
  - 延迟：`Badge tone="warning"` 文案「延迟」，主值保留但加 `text-ink-500`。
  - 停报：主值替换为「—」，下方 `InlineNotice tone="warning"` 说明「参考价暂不可用，请以检测完成时点为准」。
- **场景**：首页（F-01）、估价结果（U-15）、终价页结算金价时点（U-18）。
- **边界**：
  - 涨跌**不用红绿**：品牌红是行动色，不能承载价格文字（AGENTS §4）；上涨/下跌用中性箭头 + 灰字，仅幅度超阈值时由页面改用 `text-warning`。
  - 不做自动刷新、不做走势图（F-06 首期可降级为文案）。
  - 必须显式出现来源与时间；缺任一项则不得渲染该卡。

### 4.2 `ItemSpecCard` — 物品规格摘要

- **职责**：统一「品类 / 纯度 / 预估克重 / 件数 / 照片 / 瑕疵说明」的展示口径，同一物品在 4 个页面不再各写一套。
- **变体**：`variant: estimate | actual`（预估信息 / 检测实测）；`showPhotos`；`note?`；`action?`（如「查看全部照片」）。
- **尺寸与字号**：`Card p-4`，左图 `MediaVisual` 1:1 宽 64 `rounded-sm`；品类 `text-card-title`；辅助信息 `text-body text-muted-foreground`；克重 `PriceText size="body" tone="ink" suffix="克"`；照片计数 `text-caption text-subtle-foreground tabular`。
- **场景**：物品信息（U-06/U-07/U-08）、订单详情（U-12）、检测差异（U-27）、终价确认（U-18）。
- **边界**：
  - 只展示「事实字段」，不展示价格结论；预估价不在此卡内出现，避免与终价混用。
  - 无照片时用占位块，不留空白塌陷；图片一律走 `MediaVisual`（固定比例 + 懒加载）。
  - `variant="actual"` 时字段名必须与预估一致，差异交给 `CompareRows`。

### 4.3 `CompareRows` — 预期 / 实测对照

- **职责**：把「用户填的」与「检测出的」按同一维度并排，逐行说明差在哪；这是租赁「归还按变化计费」在回收里的等价物。
- **变体**：`columns: { key, label }[]`（默认「项目 / 预估 / 实测」）；`rows: { label, values, delta?, deltaNote?, highlight? }[]`；`highlightTone?: 'warning' | 'danger'`。
- **尺寸与字号**：容器 `rounded-md`，表头 `text-caption text-subtle-foreground`，行 `py-2 text-body`，数值列 `tabular` 右对齐；列宽 `grid grid-cols-[1fr_auto_auto] gap-3`；分隔 `border-line-soft`。
- **场景**：检测差异（U-27）、终价与预估差异（F-14）、复检前后对比（U-28，传 3 列以上）。
- **边界**：
  - 实测缺失显示「—」，不显示 0，避免误读为「归零」。
  - 差异显著性阈值由调用方传入（`highlight`），组件不内置业务阈值。
  - 差异色只用语义色，且**只在「显著差异」时上色**；常规差异用中性文字 + 括号说明「较预估 −0.8 克」。
  - 不承担解释文案：原因由 `InlineNotice` 或页面段落说明。

### 4.4 `InspectionCard` — 检测结论卡

- **职责**：承载「谁检测、怎么检测、结论是什么、凭什么、有没有影像」五件事，作为一个可核对的单元。
- **变体**：`result: consistent | divergent`；`org`、`method`、`inspectedAt`、`reportNo`；`images?: string[]`；`onViewAll?`；`footer?`。
- **尺寸与字号**：`Card p-4`；卡片标题 `text-card-title`；结论 `Badge`；字段用 `KeyValueRow`，标签 `text-body text-muted-foreground`，值 `text-body tabular`；影像缩略 4 列 `aspect-square rounded-sm`，计数 `text-caption`。
- **场景**：检测与结果（U-27）、订单详情记录中枢（U-12）、终价依据（U-18）。
- **边界**：
  - 不展示检测参数细节与内部方法参数（A-20 只要求结论、依据、影像可查）。
  - 报告下载不做（凭证下载范围未定），只给「影像可查」。
  - 结论与差异必须一致：`result="divergent"` 但无差异行时，由页面负责补 `CompareRows`，组件不自行推断。

### 4.5 `PrerequisiteList` — 前置条件清单

- **职责**：把「实名 / 绑卡 / 协议 / 电子签 / 来源声明」等准入项做成可勾完的清单，对应租赁的信用闸门。
- **变体**：`items: { key, title, description?, done, actionLabel?, onAction? }[]`；`hint?`。
- **尺寸与字号**：每行 `min-h-14 px-0 py-3`，图标 20（完成 `text-success`，待完成 `text-ink-400`）；标题 `text-body-strong`；说明 `text-caption text-muted-foreground`；右侧动作用 `Button variant="text" size="sm"`。
- **场景**：下单提交前校验（A-04）、我的-账户状态（U-20）、协议未签署/未实名/未绑卡状态页（F-03）。
- **边界**：
  - **不默认全绿**：状态由页面传入，组件不做任何推断。
  - 不展示风控原因与规则，只展示「待完成 / 审核中 / 已完成」。
  - 未完成项可点跳转，已完成项不可点（避免重复签署）。
  - 不弹 toast；未完成时的说明用行下方 `text-caption` 或 `InlineNotice`。

### 4.6 `StepIndicator` — 下单分步指示

- **职责**：告诉用户「在第几步、还剩几步」，并在返回时定位；不替代订单状态进度。
- **变体**：`total`、`current`（1 起）、`label?`。
- **尺寸与字号**：整体高 32；文案「第 2 步 / 共 6 步」`text-caption text-muted-foreground tabular`；进度条 `h-1 rounded-full bg-surface-2`，已完成段 `bg-red-500`，`transition-[width] duration-[var(--motion-base)] ease-[var(--ease-standard)]`。
- **场景**：下单 6 步（F-02：品类 → 物品信息 → 来源声明 → 协议/破检 → 寄件信息 → 电子签）。
- **边界**：
  - 不显示 6 个步骤名（375 宽放不下，且会与 `StatusSteps` 混淆）。
  - 不吸顶、不放在 `PageHeader` 内；放在内容区首行，`mb-4`。
  - 若最终改为单页分区而非分步，本组件降为 P1。
  - `role="progressbar"` + `aria-valuenow/valuemin/valuemax`。
