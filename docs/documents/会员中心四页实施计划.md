# 第二批：会员中心四页实施计划

## Context

管理端“会员中心”目前有会员列表、实名认证核验、会员标签、交易限额 4 个占位页。本批将它们全部实现为真实 mock 业务页面，并关联既有销售订单、回收订单，形成可操作的会员档案、实名审核、账号状态与交易限额闭环。

仅修改 `/workspace/gold_admin`；不修改用户端 `/workspace/gold_recycling_mini`，不修改 `/workspace/cross-end-contract.md`，不新增跨端主状态，不开发营销画像、真实实名渠道、短信、支付或风控人工审核队列。

### 已确认口径

- 默认必须实名才能购买投资金；页面保留强制实名开关及未实名限额配置。
- 累计购买额度按自然月统计。
- 冻结后已付款订单继续履约；待付款订单保留但禁止支付，不自动取消、不回补库存。
- 本批会员手机号、姓名、身份证、地址仅展示脱敏，不提供明文查看及二次验证。
- 详情和操作使用弹窗，不新增全屏详情路由；未经明确要求不 commit/push。

## 页面与路由

沿用 `createAppRouter.js` 的自动页面解析，仅在 `nav.js` 移除 4 项 `PlaceholderPage` 指定，权限继续使用 `member:view`。

| 独立路由 | 新页面 | 实施范围 |
| --- | --- | --- |
| `#/admin/member-list` | `MemberList.vue` | 关键词、实名状态、账号状态、注册时间、消费金额区间组合筛选；注册时间倒序、20 条/页；展示订单聚合、累计消费、标签、注册与最后登录时间。详情弹窗分基础、实名、地址、销售订单、回收订单、操作日志 6 个 Tab；支持冻结/解冻并必填原因。支持 `?memberId=` 打开既有详情弹窗。 |
| `#/admin/member-verify` | `MemberVerify.vue` | 全部、审核中、失败、已通过、已驳回队列及数量；按会员/手机号、渠道、提交时间筛选；详情弹窗展示脱敏资料、渠道、核验结果、失败原因与历史记录。仅“失败”记录可人工通过或驳回，驳回必填原因，提交前重读记录避免重复审核。 |
| `#/admin/member-tag` | `MemberTag.vue` | 按会员/手机号及 VIP、活跃、沉睡标签筛选；展示会员消费聚合和当前标签；弹窗手动增删标签并留痕，同步会员列表与详情。不做自动分层、营销画像和推送。 |
| `#/admin/member-limit` | `MemberLimit.vue` | 配置强制实名、已实名/未实名单笔及自然月累计额度；超限仅拦截。提供会员 + 拟下单金额的校验预演，展示本月已购、剩余额度和拦截原因；下方展示配置变更日志。配置只保存在管理端 mock，不宣称用户端结算已实时生效。 |

会员标签、实名记录及限额预演中的“查看会员”统一跳转 `member-list?memberId=...`，复用会员详情弹窗，不复制详情页。

## 数据与状态设计

### `src/apps/demo/mock.js`

- 新增不少于 24 个虚构会员，覆盖未实名、审核中、已实名、失败及正常、冻结、注销状态，确保可验证第二页分页；其中 7 个会员关联既有客户。
- 新增 `members`、`memberVerifyRecords`、单例 `memberLimitConfig`。会员字段沿用 `phone/loginAt/realNameAuth`，管理端补充不可变 `memberId`、注册时间、`accountStatus(normal/frozen/cancelled)`、标签和脱敏地址；所有敏感数据均为虚构 mock，界面只输出脱敏值。
- 给既有 `salesOrders`、`recycleOrders` 增加管理端内部 `memberId`，不修改跨端订单契约。销售订单数与消费金额实时聚合，不冗余保存：待付款、已取消不计入，其他状态按 `totalAmount` 计入；自然月额度按订单 `createdAt` 和同一有效状态集合计算。
- 实名状态由 `realNameAuth` 与最新核验记录派生：有有效 `realNameAuth.verifiedAt` 为已实名；最新记录审核中为审核中、失败为失败；人工驳回后回到未实名，驳回原因保留在核验记录。
- 审核通过写入 `verifiedAt`，审核驳回允许用户后续重新提交；审核中只读，已实名不可重复审核。不实现已失效、OCR、公安库或人脸真实核验。
- 账号仅允许 `normal ↔ frozen`，注销只读；冻结/解冻不改实名、标签或既有订单主状态，所有操作复用 `addTradeLog` 写入会员审计日志，不伪造 IP。
- 限额预演顺序：注销/冻结 → 强制实名 → 对应实名等级的单笔额度 → 自然月累计额度；等于额度允许，多 0.01 拦截，统一复用 `roundMoney`。配置变更复用交易日志保存变更前后摘要。
- 新增会员聚合、脱敏、实名派生、月度消费和限额校验等小 helpers；分页继续复用 `paginateRows`，不另造数据请求层。

### 与既有交易页联动

- `SaleOrderList.vue`：支持 `?orderId=` 打开既有详情弹窗；标记待付款订单已收款前，按 `memberId` 重读会员状态，冻结/注销时阻止支付并显示原因，不取消订单。已付款订单的其他履约动作不受冻结影响。
- `RecycleOrderList.vue`：扩展现有路由查询处理，支持 `?orderId=` 打开既有详情弹窗；不改变回收 9 态。
- 会员详情中的订单号分别跳转以上独立列表路由并打开弹窗，不新增订单详情路由。

4. 对 `SaleOrderList.vue`、`RecycleOrderList.vue` 做上述最小联动修改；页面重新激活时刷新会员、订单聚合和日志，保持 keep-alive 下跨页一致。
5. 构建、浏览器验收、产物审查后覆盖原公网资源，并回写 `.trae/hsk-publish/state.json`。

- 会员详情 6 个 Tab 数据正确；销售/回收订单跳转能打开对应既有订单详情弹窗。
