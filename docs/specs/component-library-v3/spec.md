## 结论摘要

1. 黄金回收行业的模块骨架是「**金价基准 → 品类与物品信息 → 回收方式 → 寄件物流 → 检测复检 → 报价确认 → 资金结算 → 实名合规 → 订单售后 → 门店与人员**」。与租赁不同，它的核心不是「周期管理」，而是 **「报价可信 + 检测可验 + 打款可查」** 三件事。
2. 行业三条业务线（直营门店 / 上门 / 邮寄）的模块差异**主要发生在履约段**：门店要门店与排队、上门要派单与行程、邮寄要保价与远程报价确认。**检测、报价、结算、合规四段是共用的**。**【调研 + 推断】**
3. 本项目 V0.8 只保留**邮寄线**，且多了同业少见的三段：**破检授权前置 → 72h 终价确认（超时自动接受）→ 拒绝退回 / 复检一次**。这决定了组件重心应放在「预期 vs 实测 vs 熔后复检」的对照与留痕，而不是门店、上门、锁价。
4. **对 v2 六个 P0 的复审：保留 5 个、替换 1 个、新增 1 个。**
   - 保留：`QuoteRateCard`、`ItemSpecCard`、`CompareRows`（升级为三列）、`PrerequisiteList`、`StepIndicator`（有条件）。
   - 替换：`InspectionCard` → `AssayResultCard`（必须能表达检测方式、破坏性、复检两次）。
   - 新增：`FormulaExplainer`（计价公式条），这是行业「报价透明」的核心表达，租赁类比推不出来。
5. 最终：**本期必须 7 个、后续预留 7 个、明确不做 11 类**。全部只用现有 token，无新依赖。

### 2.2 三条业务线各自需要的模块

| 模块 | 直营门店 | 上门回收 | 邮寄回收 |
| --- | --- | --- | --- |
| 金价与报价 | 挂牌价 + 当日回收价 | 同左 + 上门时段内的报价口径 | 公示价 + 估价有效期 |
| 品类与物品 | 当场看实物、钢印、发票 | 同左 | 用户自填 + 照片 + 后续实测 |

| 检测 | 透明操作台、客户可监看、当场出结论 | 便携设备当场检测 | 检测中心集中检测、录像、远程告知 |
| 报价确认 | 当面口头 + 当场确认 | 当面确认 | **远程确认 + 窗口期**（本项目为 72h） |
| 资金 | 当场打款 | 当场打款 | 预估价预付/冻结 → 质检后结算差价（行业做法）或终价后付款（本项目） |

**一句话差异**：门店与上门是「**当场闭环**」，靠人的现场可信度；邮寄是「**异步闭环**」，只能靠**流程状态 + 影像留痕 + 报价规则**建立信任。本项目属于后者，组件必须服务「异步可信」。

### 3.2 本项目与行业的五个关键差异（决定组件不照抄）

1. **不锁价，但要解释为什么不锁价。** 行业用「锁价协议」安抚金价波动；本项目规则是「终价按检测完成时点结算金价」（A-09），因此界面必须把「参考价 / 预估价 / 结算金价」三层词说清，否则用户会默认下单即锁价。**【推断，依据 A-07/A-09】**
2. **多一段「确认窗口」。** 门店/上门是当面点确认，邮寄同业多为「质检后反馈价、用户确认成交」；本项目加了 72h 超时自动接受与一次复检，是**行业里更重的一段**，需要倒计时 + 状态提示 + 复检对照。**【推断，依据 U-18/A-21】**
3. **多一条「拒绝后必须退回」的分支。** 行业公开资料很少描述「拒绝报价后如何退回」，本项目 U-28 把它做成了完整链路（退回费、物流、签收、关闭原因）。**【调研：未获取同业退回流程细节 + 推断】**
4. **平台不是自营检测。** 检测方是安盛华集团、付款方是安盛华钟表公司，用户面对三方。行业多为自营闭环，所以「谁检测、谁打款」必须显式出现在检测卡与到账凭证里。**【推断，依据 3.6 与 A-20】**
5. **只做两类品类。** 行业普遍同时标 K 金/铂金/银等价；本项目仅足金与投资金条金币，**不需要多品类牌价表**，但需要更强的「品类拦截」表达。**【推断，依据 L-02】**

### 3.3 六条「不适用但要能解释」的结论

| 行业做法 | 本项目处理 | 理由 |
| --- | --- | --- |
| 锁价 / 锁价协议 | 不做组件；用「估价有效期 + 结算金价时点」替代 | V0.8 明确按检测完成时点金价结算，无锁价规则 |
| 预付款冻结 → 差价结算 | 预留资金状态组件，等口径确认 | V0.8 只写终价后付款，未定义预付款；支付宝模式是行业做法之一，不是本项目规则 |
| 门店查询/导航/排队 | 不做 | L-01 首期仅邮寄；F-01 不得展示门店入口 |
| 上门派单/时段 | 不做 | 同上；U-10 明确不采集到店/上门字段 |
| 多品类牌价（K 金/铂金/银） | 不做 | L-02 默认拦截，非开放品类不进交易 |
| 购买凭证上传/发票说明签名 | 不做独立组件，复用 `PhotoUploader` + `AgreementCheck` | U-24 来源声明走勾选与电子签，不要求发票 |

## 四、对 v2 六个 P0 的复审

| v2 组件 | 复审结论 | 理由 | 调整 |
| --- | --- | --- | --- |
| `QuoteRateCard` 参考金价卡 | **保留** | 行业全部产品都把「挂钩 SGE + 公示时点」作为信任基石；本项目 U-14/F-06 硬要求来源与更新时间；三处复用（首页/估价/终价） | 增 `validUntil`（估价有效期）与 `status=live/delayed/halted`；文案层明确「仅参考」 |
| `ItemSpecCard` 物品规格摘要 | **保留** | 行业下单必填品类/克重/成色/照片；本项目同一物品信息在订单详情、检测、终价、退回四处出现 | 增可选 `hallmark`（钢印）、`certificate`（证书）；仍不承载价格 |
| `CompareRows` 预期/实测对照 | **保留并升级** | 行业痛点之一就是「称重瘦身、成色降档」，必须逐项对照；爱回收还有「熔后复检」第三段 | 由两列扩为**三列**（预估 / 实测 / 熔后复检）；差异列固定末列 |

## 六、P0 组件明细

> 统一约定：间距只用 4/8/12/16/24/32；圆角只用 `rounded-xs/sm/md/lg/pill`；字号只用 role 类；金额、克重、时间加 `tabular`；可点区域 ≥44×44；支持 `className`；组件内不写业务文案、不造数据。

### 6.1 `QuoteRateCard` — 参考金价卡

- **职责**：把「参考金价 + 来源 + 更新时间 + 有效性」作为一个不可拆整体，阻止页面各写一套口径。
- **变体**：`price: number`；`source: string`；`updatedAt: string`；`status: 'live' | 'delayed' | 'halted'`；`validUntil?: string`；`footnote?: ReactNode`；`onDetail?`。
- **尺寸与字号**：`Card p-4`；标签 `text-label text-muted-foreground`；主值 `PriceText size="title" tone="gold" suffix="/克"`；来源、更新时间、有效期 `text-caption text-subtle-foreground tabular`；状态 `Badge size="sm"`。
- **状态**：正常显示主值；`delayed` 加 `Badge tone="warning"`「延迟」且主值降为 `text-ink-500`；`halted` 主值显示「—」并由页面在卡下放 `InlineNotice tone="warning"`。
- **场景**：首页（F-01）、估价结果（U-15）、终价页金价时点（U-18）。
- **边界**：
  - **不显示涨跌红绿**：品牌红是行动色，不承载价格；涨跌用中性箭头 + `text-caption text-muted-foreground`。
  - 不与预估价、终价同卡展示；卡片只回答「今天的基准是多少」。
  - `source` 与 `updatedAt` 缺一不渲染，避免出现「无出处的金价」。
  - 不做走势图（F-06 首期允许降级为文案）。

### 6.2 `FormulaExplainer` — 计价公式条

- **职责**：把「怎么算出来的」摊开，落实 U-15「展示公式和参数」与 U-16「预估非终价」。
- **变体**：`factors: { label: string; value: string; unit?: string }[]`；`deductions?: { label: string; value: string }[]`；`result: number`；`resultLabel?: string`；`note?: ReactNode`；`compact?: boolean`。
- **尺寸与字号**：`rounded-md bg-surface-2 px-3 py-3`；因子 `text-caption text-muted-foreground` + 值 `text-body-strong tabular`；运算符 `text-caption text-ink-400`；结果 `PriceText size="section" tone="ink"`；`compact` 用 `text-caption` + `PriceText size="body"`。
- **形态**：`flex flex-wrap items-center gap-x-1 gap-y-2`，375 宽自动折成两行；因子之间用「×」，扣减用「−」，结果用「＝」。
- **场景**：估价结果（U-15/U-16）、终价明细（U-18）、预估与终价差异说明（F-14）。
- **边界**：
  - **纯展示，不做计算**；所有数值由页面传入，避免组件里出现业务规则。
  - **扣减项不得隐藏**：有费用就逐项列出，无费用时由页面传「无其他扣费」，组件不自行省略。
  - 不在按钮内、不在吸底栏内使用。
  - 与 `KeyValueRow` 分工：公式条讲「算法」，键值行讲「明细」。

### 6.3 `ItemSpecCard` — 物品规格摘要

- **职责**：统一「品类 / 纯度 / 克重 / 件数 / 钢印 / 证书 / 照片」的展示口径，四处复用不再各写。
- **变体**：`variant: 'estimate' | 'actual'`；`category`、`purity`、`weight`、`count`；`hallmark?`、`certificate?`；`photos?: string[]`；`note?`；`onViewPhotos?`。
- **尺寸与字号**：`Card p-4`；左图 `MediaVisual` 1:1 宽 64 `rounded-sm`；品类 `text-card-title`；辅助信息 `text-body text-muted-foreground`；克重 `PriceText size="body" tone="ink" suffix="克"`；照片计数 `text-caption tabular`。
- **场景**：物品信息（U-04～U-08）、订单详情（U-12）、检测（U-27）、终价（U-18）。
- **边界**：
  - 只放事实字段，**不放任何价格结论**，避免预估价与终价混用。
  - `variant="actual"` 时字段名必须与预估完全一致，差异交给 `CompareRows`，组件不做比较。
  - 无照片用占位块，不留塌陷；图片一律走 `MediaVisual`。
  - 品类被拦截时（K 金、镶嵌、含非金配件）由页面传 `note` 说明原因，组件不内置拦截文案。

### 6.4 `CompareRows` — 预估 / 实测 / 熔后复检对照

- **职责**：把「我填的」「你称的」「熔后复检的」按同一维度并排，让差异可逐项目核对——直接回应行业「称重瘦身、成色降档」的信任缺口。
- **变体**：`columns: { key: string; label: string }[]`（默认 3 列：预估 / 实测 / 熔后复检，传 2 列时自动退化为两列）；`rows: { label, values: (string|number|null)[], delta?: string, highlight?: boolean }[]`；`highlightTone?: 'warning' | 'danger'`。
- **尺寸与字号**：表头 `text-caption text-subtle-foreground`；行 `py-2 text-body`，数值列 `tabular text-right`；布局 `grid` 按列数生成，首列 `1fr`、数值列 `auto`；分隔 `border-line-soft`；差异列 `text-caption`。
- **场景**：检测差异（U-27）、终价与预估差异（F-14）、复检前后对比（U-28）。
- **边界**：
  - 缺失值显示「—」，不显示 0（0 会被读成「归零」）。
  - 差异是否上色由 `highlight` 传入，**组件不内置阈值**（阈值待产品定）。
  - 布尔型行（如「品类一致」）用文字，不用颜色表达。
  - 只做对照，不写解释；原因由 `InlineNotice` 或页面段落承担。
  - 列数上限 3，超过 3 列在 375 宽下不可读。

### 6.5 `AssayResultCard` — 检测与复检结果卡

- **职责**：回答「谁检测、怎么检测、是不是破坏性、结果是什么、凭什么、有没有复检」。
- **变体**：`org`、`method`（如「光谱无损」「破坏性熔检」）、`breaking: boolean`、`inspectedAt`、`assayNo?`；`weight`、`fineness`、`meltWeight?`；`images?: string[]`；`recheck?: { org, at, conclusion, delta? }`；`result: 'consistent' | 'divergent'`；`footer?`。
- **尺寸与字号**：`Card p-4`；标题 `text-card-title` + 结论 `Badge`；字段用 `KeyValueRow`，值 `tabular`；影像 4 列 `aspect-square rounded-sm`；`breaking` 为真时在卡内固定位置放 `InlineNotice tone="warning"`，文案由页面传入；复检区块用 `border-t border-line-soft pt-3` 分隔。
- **场景**：检测进度与结果（U-27）、订单详情记录中枢（U-12）、终价依据（U-18）。
- **边界**：
  - **破坏性必须显式**：`breaking=true` 时不允许隐藏提示位，这是 U-25 与行业告知义务的共同要求。
  - 不展示检测内部参数、设备型号、人员姓名。
  - 不承诺报告下载（凭证下载范围未定），只给「影像可查看」。
  - 复检只能有一次：`recheck` 为单对象，不是数组，避免界面暗示可多次复检。
  - 结论与差异不自行推断：`result` 由页面给定。

### 6.6 `PrerequisiteList` — 前置条件清单

- **职责**：把「实名 / 本人银行卡 / 协议 / 电子签 / 来源声明」五项做成可勾完的清单，对应 A-04 的下单前校验。
- **变体**：`items: { key, title, description?, done, actionLabel?, onAction? }[]`；`hint?`。
- **尺寸与字号**：每行 `min-h-14 py-3`；状态图标 20（完成 `text-success`，待完成 `text-ink-400`）；标题 `text-body-strong`；说明 `text-caption text-muted-foreground`；右侧 `Button variant="text" size="sm"`。
- **场景**：下单提交前（A-04）、我的-账户状态（U-20）、未实名/未绑卡/未签协议状态页（F-03）。
- **边界**：
  - 状态全部由页面传入，组件不推断、不默认全绿。
  - 不显示风控原因与规则（F-09），只显示「待完成 / 审核中 / 已完成」。
  - 已完成项不可点，避免重复签署。
  - 未完成说明用行下 `text-caption`，不弹 toast。

### 6.7 `StepIndicator` — 下单分步指示

- **职责**：告知「第几步、还剩几步」，支撑 F-02 的分步引导与返回不丢信息。
- **变体**：`total`、`current`（1 起）、`label?`。
- **尺寸与字号**：整体高 32；文案「第 2 步 / 共 6 步」`text-caption text-muted-foreground tabular`；进度条 `h-1 rounded-full bg-surface-2`，已完成段 `bg-red-500`，`duration-[var(--motion-base)] ease-[var(--ease-standard)]`。
- **场景**：下单六步（品类 → 物品信息 → 来源声明 → 协议/破检 → 寄件信息 → 电子签）。
- **边界**：
  - 不显示六个步骤名（375 宽放不下，且会与 `StatusSteps` 混淆）。
  - 不吸顶、不放进 `PageHeader`；置于内容区首行 `mb-4`。
  - 若最终改为单页分区，本组件降 P1。
  - `role="progressbar"` + `aria-valuenow/min/max`。

### 9.2 实现中的偏差

1. `ItemSpecCard` 的 `variant` 不用文案区分（不内置「预估 / 实测」字样），改为克重语气区分：`estimate` 用 `gold`、`actual` 用 `ink`，标签由 `weightLabel` 传入。
2. `QuoteRateCard` 不提供涨跌 props，从接口层杜绝红绿涨跌；状态徽标也避开红色系（延迟 `warning`、停报 `muted`）。
3. `AssayResultCard` 用 TypeScript 联合类型强制 `breaking: true` 时必须传 `breakingNote`，编译期保证「破坏性提示不可隐藏」，不依赖运行时兜底文案。
4. 检测影像与物品照片的查看走 `BottomSheet + Gallery`，只读不留存，样张页用同一套交互演示。
5. 组件内的字段名（检测机构 / 检测方式 / 复检结论等）通过 `labels` 可覆盖，默认值只作兜底，避免页面重复声明。
