## 1. 业务边界与目标

### 1.1 业务定位

安盛华黄金回收业务首期定位为：**面向个人客户的线上邮寄黄金回收闭环服务**。用户通过微信手机号授权登录，在线完成看价、估价、下单、协议与来源确认、寄件；平台运营主体提供入口与交易记录，安盛华钟表公司作为回收与付款主体，安盛华集团完成检测，物流与保价方承接邮寄履约，最终完成终价确认、回收款支付，以及退回、复检和售后处理。

长期方向仍服务于“投资金销售＋黄金回收”的双业务规划。

### 1.2 业务目标

首期目标不做全品类，先把邮寄黄金回收主闭环跑通，并保证交易可信：

1. **实物交付前理解规则**：用户在寄件前明确品类范围、参考金价、预估逻辑、费用、强制保价、检测、默认破检授权、终价确认和退回规则。
2. **检测后理解终价**：检测完成后展示实际可熔重量、纯度、结算金价时点、服务费及其他扣减、最终应付金额；终价确认页必须与预估差异可解释。
3. **接受或拒绝后有明确操作**：接受或超时自动接受后进入付款；窗口期内拒绝后进入退回或复检；付款失败、退汇、换卡、物流异常均有处理路径。
4. **交易后查询完整记录**：订单详情串联主体、物品、协议、电子签、物流、检测、终价、支付、退回、复检、客服和争议记录。
5. **为双业务沉淀底座**：账户、订单、协议版本、电子签、支付记录、客服与售后记录按可回收复用方式设计，但交易主体、资金、协议和售后责任与投资金销售隔离。

### 1.3 首期业务范围

| 业务范围 | 业务说明 |
| --- | --- |
| 客户类型 | 仅个人客户；登录方式为微信手机号授权；不开放企业客户、对公账户结算、企业批量回收。 |
| 回收方式 | 仅邮寄回收；保留门店页展示 1 家邮寄服务门店（不接待到店交金）；不提供到店、上门、智能回收机、门店预约。 |
| 回收品类 | 足金首饰、投资金条/金币。 |
| 交易主线 | 看价/估价 → 填写物品与寄件信息 → 实名及收款准备 → 协议/来源/破检授权确认 → 首次交易电子签 → 寄件 → 签收 → 检测 → 终价确认 → 支付 → 完成；异常分支含取消、拒收、信息不符复核、退回、复检、付款失败、退汇、换卡、争议。 |
| 管理端 | 需要支撑订单、检测、终价、支付、退回/复检、用户实名、协议与电子签版本、品类/价格/费用、物流保价、风控审核、客服工单和核心指标查看。 |

### 1.4 首期不做功能

| 不做项 | 处理方式 |
| --- | --- |
| 到店回收、上门回收、智能回收机、门店预约 | 首期不做；信息架构保留门店页，仅展示 1 家邮寄服务门店，不提供到店/上门入口与预约。 |
| 铂金、白银、钯金、K金、镶嵌珠宝及其他非开放品类 | 不提供入口；下单页做范围提示和拦截，避免误寄；如后续放开，只收可熔部分并单独配置折算与扣减规则。 |
| 企业客户、对公结算、批量回收 | 首期不做；登录仅微信手机号授权，不提供企业认证入口；后续如识别企业/对公诉求，转人工线索，不进入回收交易流程。 |
| 小 B 渠道分润、渠道归属计奖 | 首期不做；仅保留订单状态、支付完成、异常审核等数据口径，便于后续试点。 |
| 会员、社区、案例、C 端拉新、测金记录、用户历程 | 首期不做；核心交易稳定后再迭代。 |
| 自有精炼、熔金、再生产或再流通 | 首期不作为上线前提；检测由安盛华集团完成，精炼及金料后续流转按集团/外部协同方案设计。 |
| 投资金销售商品、定价、交付、发票和售后 | 不在本清单；仅预留账户、订单、客服和交易记录的协同边界。 |
| 税务代扣、发票开具 | 首期不考虑；不设计个税代扣、发票开具或税务申报功能。是否保留合规提示语，由法务最终确认。 |

### 1.6 阶段验收目标

| 目标 | 验收口径 |

| 价格可解释 | 参考金价、预估单价、预估金额、估价有效期、结算金价时点、实际可熔重量纯度、费用扣减、最终应付金额在订单中可区分。 |

### 3.7 订单状态机设计

> 设计共识（2026-11-15 用户确认）：回收订单即一个业务单，一个业务单下挂物流单、付款单。订单状态、物流状态、支付状态分域管理，不混入单一状态枚举；用户侧订单状态不存在"异常"，异常以状态内提示层＋操作入口呈现。

#### 3.7.1 对象模型与职责边界

| 对象 | 回答的问题 | 状态归属 | 与订单的关系 |
| --- | --- | --- | --- |
| 回收订单（业务单） | 这单生意进行到哪一步 | 订单主状态机（9 个状态） | 主对象，串联全部单据与记录 |
| 物流单（寄出/退回各一张） | 货到哪了 | 物流子状态机 | 一单一状态；寄出运单的揽收/签收事件驱动订单主状态迁移 |
| 付款单 | 钱付没付成、失败为什么 | 支付子状态机 | 一个订单对应一笔付款义务，可有多次支付尝试；支付成功事件驱动订单进入已完成 |
| 检测工单 | 检测结果出没出、有无差异 | 内部状态 | 只向订单输出结果（检测完成/信息不符复核），用户不直接见工单状态 |

设计原则：一个字段一个职责；状态原子化、单向流转、终态不可变；逆向分支（取消/退回）进终态，不在主状态里逆行；自动迁移首期只保留终价超时自动接受一个任务，未寄出不自动关闭、不自动提醒（MVP 口径）。

#### 3.7.2 订单主状态机（9 个状态）

```
【主链】待寄出 → 待签收 → 检测中 → 待确认 → 待打款 → 已完成

【分支与终态】
待寄出 ──用户自助取消──→ 已取消
待签收 ──客服拦截退回 / 物流异常理赔完成后──→ 已关闭
检测中 ──人工判定拒收，退回签收后──→ 已关闭
待确认 ──申请复检（每单限1次，倒计时暂停）──→ 复检中 ──二次终价，重开确认窗口──→ 回到待确认
待确认 ──用户拒绝，退回签收后──→ 已关闭
待打款 ──持续支付失败 / 风控不通过，人工关闭──→ 已关闭
任意进行中状态 ──风控复核不通过，人工终止──→ 已关闭
```

| 编码 | 状态 | 进入条件 | 用户可执行操作 |
| --- | --- | --- | --- |
| 1 | 待寄出 | 订单创建成功（实名＋电子签＋协议/来源/破检授权＋强制保价校验通过） | 查看寄件指引、回填单号/物流下单、**自助取消（首期唯一取消点）** |
| 2 | 待签收 | 寄出运单已揽收 | 查看物流轨迹；取消仅可联系客服拦截 |
| 3 | 检测中 | 平台签收＋开箱留证完成 | 等待结果；信息不符时查看差异说明、配合复核 |
| 4 | 待确认 | 终价明细生成，启动 72h 倒计时 | **接受终价 / 拒绝并退回 / 申请复检**；二次终价场景下无复检选项，仅可接受或拒绝退回 |
| 5 | 复检中 | 窗口期内申请复检（每单限一次），确认倒计时暂停 | 等待复检结果 |
| 6 | 待打款 | 用户接受终价 或 超时自动接受 | 查看付款进度；支付失败时换卡重付 |
| 7 | 已完成 | 付款单支付成功（终态） | 查看凭证、下载记录 |
| 8 | 已取消 | 待寄出阶段用户自助取消（终态） | — |
| 9 | 已关闭 | 拒收退回完成 / 拒绝终价退回完成 / 拦截退回或物流异常理赔完成 / 支付异常人工关闭 / 风控终止（终态，按关闭原因分类留痕） | 查看关闭原因与退回单号 |

关键设计点：

- **"支付异常"不进订单主状态**：订单到"待打款"即停，钱没付成是付款单的事；页面从付款单读取失败原因与操作入口。
- **"物流异常"不进订单主状态**：货在"待签收"卡住是物流单的事；异常只生成工单，人工判定订单走向，不做自动迁移。
- **"复检中"必须是独立主状态**：72h 超时自动接受是已确认规则，复检期间必须暂停倒计时，独立状态是最不易出错的实现；复检每单限一次，二次终价为最终检测结论（平台不再议价、用户不可再次申请复检），生成后回到"待确认"并重开完整确认窗口，用户对二次终价仍可接受或拒绝退回。
- **退回不进主状态枚举**：拒绝终价/拒收 → 生成退回运单 → 退回签收 → 订单进"已关闭"；退回轨迹从退回运单查看。

#### 3.7.3 物流子状态机（挂在物流单上）

- 寄出运单：`待揽收 → 运输中 → 已签收`；旁路 `异常（破损/丢失/超时/拒收）→ 工单人工处理`。
- 退回运单：`待揽收 → 运输中 → 已签收 → 触发订单进入已关闭`。
- 事件驱动：揽收事件推订单 待寄出→待签收；签收事件推订单 待签收→检测中。异常不产生自动迁移。

#### 3.7.4 支付子状态机（挂在付款单上）

```
待支付 → 支付中 → 支付成功（终态，推订单进入"已完成"）
             ├→ 支付失败（限额/账户不符）→ 用户换卡 → 重新发起 → 支付中
             └→ 退汇待复核（人工复核）→ 确认/换卡 → 重新发起 → 支付中
```

- 触发方：终价确认后生成结算单，三一致（出售人/实名人/收款人）校验通过，系统自动发起付款（待支付 → 支付中）；风控命中则挂起不发指令。
- 每次重新发起为一次新支付尝试，旧尝试留痕；靠幂等键防重复付款。
- 风控审核挂"待支付"上的拦截标记，不发出付款指令；用户侧统一显示"审核中"，不披露风控规则。
- 争议工单与风控拦截同机制：挂起期间暂停所在状态的时间驱动自动迁移（终价超时自动接受、付款发起），工单处理完结后恢复计时或放行。
- 退回物流与资金状态分别闭环（A-12 口径不变）。

#### 3.7.5 主状态迁移规则

| 迁移 | 触发方 | 前置条件/规则 | 必须留痕 |
| --- | --- | --- | --- |
| 创建 → 待寄出 | 系统 | 实名＋法大大电子签＋协议/来源/破检授权＋强制保价全部通过；生成估价快照 | 协议版本、签署证据、估价快照 |
| 待寄出 → 已取消 | 用户 | 首期唯一自助取消点，无费用 | 取消原因、时间 |
| 待寄出 → 待签收 | 物流单揽收事件 | 单号有效且揽收 | 物流单号、保价信息 |
| 待签收 → 已关闭 | 客服/人工 | 客服拦截退回成功，或物流丢失进入保价理赔；退回签收或理赔完成后关闭 | 拦截/理赔工单、退回运单、关闭原因 |
| 待签收 → 检测中 | 物流单签收事件＋检测方 | 开箱留证、复称完成 | 开箱影像、复称记录 |
| 检测中 → 待确认 | 系统 | 检测工单完成，按检测完成时点金价生成终价明细 | 检测工单、终价版本、结算金价快照 |

| 任意进行中状态 → 已关闭 | 风控/人工 | 下单复核不通过、检测发现调包嫌疑、风控复核不通过等，人工复核后终止 | 复核结论、终止原因、责任人 |

## 4. 协议与页面文案草案

> 以下为产品侧草案，用于法务改写；涉及金额、期限、损耗、赔付的【占位】必须填明数后才能上线。

### 4.1 破检授权、不可还原提示与损耗口径草案

**关键条款速览建议文案：**

- 为确定黄金成色与可熔重量，安盛华集团检测人员可能对物品进行破坏性检测，包括但不限于剪开、压片、熔样、光谱/火试等检测方式。
- 破坏性检测可能造成物品形态、结构、焊点、配件、镶嵌物发生不可逆改变或灭失；即使后续退回，退回物也可能为检测后状态。
- 非金配件、镶嵌物不计入可熔结算重量；如后续开放特殊品类，是否拆除、是否返还、如何作价以当期协议和终价明细为准。
- 最终应付金额以检测完成时点的结算金价、实际可熔重量、实际纯度及费用明细计算；预估金额仅为参考，不作为最终结算依据。

**授权确认文案：**

本人已阅读并理解：本次回收默认需要破坏性检测，检测过程可能不可逆改变或灭失物品原有形态、结构、焊点、配件或镶嵌物。本人同意安盛华集团按检测标准进行检测，并同意最终回收款按检测后的实际可熔重量、实际纯度、检测完成时点结算金价及已公示费用明细计算。检测及损耗规则以【规则版本/链接】为准。

### 4.2 终价确认与超时规则草案

- 终价确认窗口建议为【72】小时；窗口期内通过小程序订阅消息、短信、站内消息进行至少【2】次提醒。
- 窗口期内用户可选择接受终价、拒绝终价并退回、申请复检；不允许二次议价。
- 申请复检后确认倒计时暂停；复检每单限一次，复检结论为最终检测结论，对双方均有约束力；二次终价生成后重开完整确认窗口，用户可接受或拒绝退回，不可再次申请复检。
- 用户超时未确认，视为接受终价并进入待打款；系统保留终价发送时间、提醒记录、超时时间和自动接受记录。
- 不采用“逾期视为放弃所有权”“没收式处置”或“联系不上即自动低价成交”的写法。

### 4.3 估价有效期草案

- 估价结果仅为提交订单前参考，有效期为【占位】；超过有效期未提交订单，需重新估价。
- 订单提交成功后，系统保存下单时参考金价、预估单价、预估金额和协议版本快照；最终结算以检测完成时点结算金价、实际可熔重量/纯度和费用明细为准。
- 首期 MVP 不做未寄出自动提醒与自动关闭；长期未寄出订单由管理端筛选人工跟进。
- 检测完成时点结算金价与下单预估金额差异超过【±X%】时，终价确认页进行显著差异提示。

### 4.4 支付异常处理草案

- 支付失败时，订单主状态保持"待打款"，失败状态与原因记录在付款单上；页面在待打款状态下展示失败原因和下一步操作；常见原因包括银行卡限额、账户信息不符、银行退回/退汇、风控审核、系统异常。
- 银行卡限额或账户信息不符：用户可更换本人银行卡，重新通过银行卡要素校验后发起重付。
- 银行退汇：付款单进入"退汇待复核"，由人工复核账户信息；用户确认或更换收款账户后重付。
- 风控审核：涉及大额、可疑、频繁或异常交易的，暂停付款并进入人工复核；页面对用户展示"审核中"，不披露具体风控规则。
- 支付成功：展示付款方安盛华钟表公司、收款账户脱敏信息、金额、支付时间、流水号/凭证；订单详情可查询资金记录。

## 5. 仍需确认/上线前必须填明数的事项

1. 强制保价的赔付基数、免责条件、处理时限、保价费金额或公式。
2. 服务费、运保费、退回费、检测相关费用是否收取及明数/公式。
3. 参考金价源、结算金价时点定义、估价有效期时长、金价波动提示阈值。
4. 终价确认窗口是否确定为 72 小时；阶梯提醒次数与渠道。
5. 信息不符复核的用户响应窗口时长（建议与终价窗口同参数 72 小时）。
6. 法大大电子签的签署文件清单、复用规则、失败路径、证据调取方式。
7. 默认破检的具体检测方法、合理损耗/误差口径、影像或报告留存期限。
8. 安盛华科技公司、安盛华钟表公司、安盛华集团之间的服务/协同协议与责任边界。
9. 税务与凭证首期不做，但是否保留一句合规提示语，由法务确认。
10. 寄出率指标的统计时间窗口径；"长期未寄出"管理端筛选视图的跟进规则。
